# REL-002 — Production Config Validation
Priority P1. Status INDEPENDENT_REVIEW_PASS / DEPLOYMENT_PENDING. Base 68878b6. Implementation 961c51b plus review fixes e62d252 and 9ab017e. Owner Work agent; acceptance Commander.

## Scope
Find every JWT secret consumer and mode resolver, including signing/verification and mock endpoints. Centralize minimal startup validation before database connection, scheduler, HTTP listen or external call. In NODE_ENV=production or any enabled real integration, missing/blank/default dev-secret JWT must fail startup with actionable variable names, never values. Reject invalid mode strings and contradictory enabled mock payment behavior in production. Validate required fields only for enabled real providers; disabled Alipay must not require its credentials. Keep explicit local mock development possible.

## Acceptance
Test absent/empty/whitespace/default secret, invalid modes, production+mock payment bypass, real-provider required fields, disabled-provider exemption and valid explicit local mock settings. Confirm no sign/verify code retains independent unsafe fallback. Verify failure occurs before side effects through startup-level test; messages contain no secrets. Backend typecheck/full Jest and safe boot smoke test.
Document environment requirements in .env.example/deployment guidance without real credentials. No production env mutation, provider mode change or paid activation.

## Implementation
- `main.ts` validates before dynamically importing `AppModule`, so invalid config is rejected before Nest constructs providers, Prisma can connect, schedules start, HTTP listens, or providers can make calls.
- `startup-config.ts` is the single resolver for JWT fallback and all `mock|real` modes. Auth signing and verification now share its JWT value; application code has no separate `dev-secret` fallback.
- Production rejects an unsafe JWT, mock WeChat payment, enabled mock Alipay, and the payment simulation endpoint. Any enabled real integration also requires a non-example JWT outside production.
- Production also rejects mock WeChat authentication and mock WeiQian signing. Tencent eSign may remain mock because it is not the active signing path.
- Each enabled real provider requires only its own fields. Disabled Alipay is exempt even if its unused mode is `real`. Explicit all-mock local development remains valid.
- `.env.example` and `deploy/CONFIGURATION.md` document the mode hierarchy, provider field matrix, production restrictions, and added WeChat Pay public-key fields without credentials.
