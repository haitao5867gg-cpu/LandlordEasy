# REL-003 — CI Quality Gate
Priority P1. Status IMPLEMENTED / ACTIONS_EVIDENCE_PENDING. Implementation base 68878b6; acceptance Commander.

## Required workflow
GitHub Actions on pull requests targeting dev/main and suitable branch pushes, with minimal contents:read permission; no deploy, SSH, repository secrets or production DB. Pin Node/pnpm from supported project versions and keep frozen lockfile installs. Cache only dependencies.
1. pnpm install --frozen-lockfile
2. pnpm --filter server exec prisma generate
3. pnpm --filter server exec tsc --noEmit
4. pnpm --filter server test -- --runInBand (verify exact Jest argument invocation)
5. pnpm --filter landlord-h5 exec vue-tsc -b plus build
6. pnpm --filter tenant-h5 exec vue-tsc -b plus build

## Acceptance
All six commands execute on exact candidate and fail the required check on error. Use synthetic config; no production credentials, DB or real providers. Do not run seed/import/db push or deployment scripts. PDF/browser dependencies documented; don't quietly skip tests.
Review permissions, events, untrusted PR handling (no pull_request_target code execution), timeout/concurrency, supply-chain pins and logs. Avoid unnecessary dependency upgrades.
Show real Actions run URL/check SHA and a safe deliberate failure proving check reports failure where practical. Inspect branch protection/ruleset requirement separately: a green workflow alone does not prevent merges. Record absent enforcement as gap; prepare exact required check recommendation before changing repository settings.
Do not merge failing CI or report absent CI as passed. No CD in this spec.

## Implementation and local evidence (2026-09-06 UTC)

Workflow: `.github/workflows/ci-quality-gate.yml`. It exposes one check named `REL-003 quality gate`, triggered by pull requests targeting `dev`/`main` and pushes to `main`, `dev`, `release/**`, `fix/**` and `ci/**`. Repository token permissions are limited to `contents: read`; the workflow has no deploy step, database mutation, production credentials, provider calls, SSH or `pull_request_target` execution. Concurrency cancels superseded runs on the same ref and the job has a 30-minute timeout. The synthetic test environment fixes `TZ=UTC`, matching the date-only assumptions in the existing bill-engine suite and avoiding host-timezone-dependent results.

Supply-chain inputs are fixed: Ubuntu 24.04, Node 20.19.5, pnpm 9.15.9, and action references pinned to immutable commit SHAs. The `pnpm/action-setup` pin uses the peeled commit SHA rather than the annotated `v4` tag object's SHA, which does not resolve through GitHub's raw-content endpoint. `actions/setup-node` caches only pnpm's dependency store using `pnpm-lock.yaml`; `node_modules` and build outputs are not cached. Installation uses the frozen lockfile.

The PDF test remains enabled. CI installs the Playwright-version-matched Chromium headless shell plus runner system dependencies, resolves the installed executable, verifies it is executable and exports `PDF_CHROME_EXECUTABLE_PATH` before full Jest. Failure to install or resolve the browser fails the job.

The required Jest argument was tested explicitly under the pinned pnpm 9.15.9. `pnpm --filter server test -- --runInBand` invokes `jest --runInBand` and discovers all 15 suites. Omitting the separator (`pnpm --filter server test --runInBand`) fails in pnpm 9.15.9 with `Unknown option: 'runInBand'`; the workflow therefore retains the required separator and does not skip any suite.

Local verification used the isolated Linux worktree at base `68878b6bb0245d328c8cb82a34f468ff37f28f7a`. The implementation run used Node 24.19.0 and pnpm 11.19.0. Independent review reran the commands with pnpm 9.15.9 through Corepack and `TZ=UTC`; the real Actions run must separately prove the pinned Node 20.19.5 environment.
