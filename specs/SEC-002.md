# SEC-002 — Payment Authorization
Priority P1. Status LOCAL_VERIFIED / INDEPENDENT_ACCEPTANCE_PENDING. Base stack 68878b6 (SEC-001 included). Implementation owner: Work agent; acceptance: Commander.

## Problem
Handoff reports POST /payments/report authenticates a tenant but accepts another tenant's billId. Existing design section 5.3 retires manual tenant reporting; verify all callers before choosing removal.

## Scope and decision rule
Search route, services, both H5 apps, tests and historical pending-payment workflows. If reporting is unused, remove the report route/DTO/service capability and references without deleting payment records or breaking landlord confirmation of existing records. If it remains required, enforce bill.lease.tenantId === JWT tenant ID server-side before any write; never trust supplied tenantId. Missing/foreign bills must not disclose details. Preserve manual landlord entries and real gateway callback validation.

## Acceptance
- Unauthenticated request rejected; tenant A cannot report tenant B's bill and creates no records.
- If removed: former route cannot create records for any identity; legitimate payment/manual/history flows remain intact.
- If retained: own-bill success, foreign/missing bill rejection, invalid amount/status, duplicate handling follow existing rules.
- Backend full Jest/typecheck; changed frontend checks/browser if applicable. Record exact commit and caller-search evidence.
- No production DB or payment call. Independent diff/test verification; open until all evidence passes.

## Non-goals
Payment redesign, Alipay enablement, deleting historical records or changing settlement rules.
