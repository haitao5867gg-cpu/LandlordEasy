# SEC-001 — Contract Access Control

Priority: P0. Status: LOCAL_VERIFIED; deployment acceptance PENDING. Baseline: dev `d58097e`. Owner: Commander; implementation: assigned engineering worker; acceptance: independent review.

## Problem and evidence

`leases.service.ts` writes predictable preview/signed PDFs to `data/uploads`; `app.module.ts` serves uploads without authentication; both server blocks in `deploy/nginx.conf` expose uploads directly. A login guard on the preview-generation POST does not protect the resulting static file.

## Required behavior

- Store every newly generated, previewed and archived contract outside public static roots. Do not use randomness as authorization.
- Every PDF read checks authentication and current permission before reading files or calling the provider. Existing active landlord whitelist grants shared portfolio access (current schema has no per-landlord property ownership). Do not invent a landlord-owner relationship. Tenant access requires task.lease.tenantId equal authenticated tenant ID; signed contracts only, including historical own leases. Tenant must never access another tenant's contract or landlord progress preview.
- Use authenticated binary download APIs with application/pdf, attachment filename, Cache-Control private/no-store and nosniff. Tokens must not appear in URLs. Do not accept arbitrary filesystem paths or fetch arbitrary stored URLs.
- Preserve landlord preview vs confirmation semantics: preview must not change status/signedAt, consume a new signature, or imply completed signing. Keep current manually confirmed signing business rules intact.
- Update landlord buttons to fetch authenticated blobs with loading/error recovery. Provide the tenant's own signed-contract discovery/download entry within the existing lease journey; this is a V1 access gap, not new business scope.
- Handle legacy signedPdfUrl values safely. Prepare an idempotent, dry-run-first migration for existing public PDFs with conflict/integrity checks. Do not execute against dev/prod data in this task. No public fallback.
- Block legacy contract URLs in both Nest static serving and Nginx, including existing files and encoded/case variations; preserve legitimate non-contract uploads where safe. Inspect actual location precedence. Add rollout/rollback instructions that never reopen public access.

## Acceptance and evidence

- Unauthenticated, invalid-token, tenant wrong-role, cross-tenant, disabled-landlord, missing-task/file and path-traversal attempts fail without PDF disclosure or provider read.
- Valid active landlord preview/download and own tenant signed download succeed; own historic signed contract remains accessible; tenant preview denied. Verify response headers and binary contents through HTTP-level tests with guards active.
- Old public URLs fail in app and deployed proxy, even when old files exist. Tests should demonstrate bypass attempts, not merely assert method calls.
- Migration dry run makes no changes; repeated application is safe; differing destination aborts without deleting source; matching copy verified before removing public source. Files/symlinks outside configured roots must not be read or moved.
- Backend typecheck + full Jest; both affected frontend typechecks/builds; real browser walkthrough of changed interactions. Record mock fixtures vs real integration explicitly.
- Actual server/proxy migration and real WeChat browser download are release gates. Local success does not close the deployed P0.

## Out of scope

Contract wording, authType, e-sign business semantics, cloud storage redesign, production deployment/data mutation, new costs or notifications to real recipients.
