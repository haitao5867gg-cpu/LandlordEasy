1) P0/P1 CODE FINDINGS

P0-1 (code defect) — apps/server/src/leases/leases.service.ts, function endLeaseInTransaction (~lines 688-699), reached from both approveTerminationRequest and approveTransferRequest. Failure mode: the ACTIVE-status guard (`if (lease.status !== 'ACTIVE') throw`) reads via a plain `db.lease.findUnique` issued *after* this function's own `SELECT ... FOR UPDATE` on the leases row. Under InnoDB REPEATABLE READ, a transaction's plain (non-locking) reads all reuse the snapshot fixed by the FIRST plain read in that transaction — here that is the outer request row's own findUnique (leaseTerminationRequest/roomTransferRequest), which happens before the leases-row lock is even taken. So the later plain lease read can still return pre-commit data even though the row lock is now held — this is the identical bug class specs/REL-001.md's 2026-09-09 checkpoint diagnosed and fixed for the room claim, just unfixed here for the lease-status transition. It is reachable because createTerminationRequest and createTransferRequest (same file, ~L794 and ~L946) each only dedupe PENDING requests of their own type, so one lease can carry a PENDING termination request and a PENDING transfer request simultaneously; approving both around the same time lets each transaction observe ACTIVE and both attempt to end the same lease — duplicate deposit/bill records and inconsistent room state, violating REL-001's 'duplicate/concurrent approval must produce one result' invariant. Minimal remediation: mirror the already-applied room fix — replace the read-then-branch with `db.lease.updateMany({ where: { id, status: 'ACTIVE' }, data: { status: 'ENDED', endedAt, endReason } })`, require `count === 1` before any deposit/bill/room write, and keep the existing findUnique only for reading immutable fields (deposit amount, roomId) needed for refund math.

P1-A (code defect, contributing precondition) — apps/server/src/leases/leases.service.ts, createTerminationRequest (~L794) and createTransferRequest (~L946). Neither checks for a PENDING request of the other type on the same lease. Remediation: reject creation if a PENDING request of the other type already exists for that leaseId (defense in depth; does not by itself close P0-1, which needs the atomic-claim fix).

P1-B (code/test-coverage defect) — apps/server/src/leases/__mysql-integration__/rel001-termination.mysql-integration.spec.ts, rel001-transfer.mysql-integration.spec.ts, rel001-concurrency.mysql-integration.spec.ts.
